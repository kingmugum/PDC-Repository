PassFail 요구사항 이중 계층화 안내

기준일: 2026-09-06
배포 패키지: PassFail_260906_1.zip
소프트웨어 기준: rev85 (코드 변경 없음)
요구사항 문서: PassFail_Requirements_Management_rev86.xlsx

1. 이번 변경 범위
- 기존 PassFail rev85 실행 코드와 CAPL 템플릿은 변경하지 않았습니다.
- 요구사항 Excel을 사람용 상위 시나리오와 AI용 상세 요구사항의 이중 계층으로 재구성했습니다.
- 기존 FR-001~FR-159는 삭제하거나 재번호를 부여하지 않았습니다.

2. 사람이 보는 시트
- 맨 앞의 `사용자 시나리오` 시트만 일상 검토 대상으로 사용합니다.
- 열 구성: 시나리오 ID, 시나리오명, 사용자 목적·상황, 사용자 시나리오, 기대 결과, 관련 FR ID, 현황
- 기존 FR과 코드 이력에서 역추적한 23개 시나리오는 모두 최초 `검토중` 상태입니다.
- 사용자가 내용이 의도와 같다고 확인한 시나리오만 `일치`로 변경합니다.

3. AI가 보는 시트
- AI_01_문서목적·운영규칙
- AI_02_요구사항목록
- AI_03_판정기준
- AI_04_실패상황
- AI_05_변경금지조건
- AI_06_디버깅체크
- AI_07_회귀테스트
- AI_08_코드근거
- AI_09_AI작업규칙
- AI_10_요구사항충돌검토

4. 추적성
- 사용자 시나리오의 `관련 FR ID`와 AI_02의 `상위 시나리오 ID`가 양방향으로 연결됩니다.
- FR-001~FR-159는 빠짐없이 하나의 상위 시나리오에 귀속되어 있습니다.
- AI_02에 `요구사항 유효성`, `대체 요구사항 ID`, `요구·변경 근거` 열을 추가했습니다.

5. 정합성 정리
- FR-007은 과거 GetActiveObject-only 정책 기록으로 보존하되 `대체됨`으로 표시했습니다.
- 현행 Vector 연결 정책은 FR-073~FR-077을 따릅니다.
- GetActiveObject를 우선하고, 기존 제품 주 프로세스 확인 시에만 guarded Dispatch를 최대 한 번 허용합니다.
- DispatchEx, 무조건적인 새 인스턴스 생성, Registry 쓰기는 금지하며 진단 기능은 read-only입니다.
- FR-046은 rev85 코드에 구현된 bus_warning 분리 정책을 확인하여 `구현됨`으로 정정했습니다.
- FR-117 상태 셀의 잘못된 장문 값을 `구현됨`으로 복원했으며 안전 제약 문구는 원래 상세 열에 유지했습니다.

6. 검증 범위
- 시트 순서와 이름, FR ID 연속성, 23개 시나리오의 FR 전체 포함·중복 없음, 상호 링크, 수식 오류를 확인했습니다.
- 새 요구사항 Excel은 ZIP 내부 파일과 동일한 파일입니다.
- 현장 CANoe/CANalyzer 및 차량 회귀시험은 이번 문서 변환에 포함되지 않았으며 기존 수행 상태를 AI_07에 그대로 보존했습니다.

7. 다음 사용자 검토
- 먼저 `사용자 시나리오`의 23개 행만 읽고 의도와 같으면 현황을 `일치`로 변경합니다.
- 차이가 있는 시나리오는 현황을 `불일치`로 표시한 뒤 수정 의도를 전달합니다.
- 시나리오 승인만으로 연결된 FR을 자동 변경하지 않습니다. 필요한 FR 수정은 별도 변경 절차로 수행합니다.
