PassFail rev85 - Stimulus 최신 BLF/ASC 자동 검증 안내
=====================================================

1. 목적
- 차량 송수신 테스트에서 Stimulus를 실행한 뒤 CANoe Trace를 직접 일일이 확인하지 않아도,
  설정 탭의 '자동 로그 폴더'에 생성된 최신 BLF/ASC를 읽어 실제 Message/Signal 변화 여부를 보여줍니다.
- 이 기능은 디버깅/버스 증적 확인용이며 차량 기능 PASS/FAIL 판정기는 아닙니다.

2. 기본 동작
- 차량 송수신 테스트 > 수동 후보 Signal 묶음 테스트 영역에
  [Stimulus 후 최신 BLF/ASC 자동 검증] 체크박스가 추가되며 기본 ON입니다.
- Stimulus 실행/원복 후 Measurement Stop까지 끝나면 실행 시작 시각 이후의 최신 BLF/ASC를 찾습니다.
- 로그 파일이 안정화된 뒤 DBC로 target Message를 decode합니다.
- 별도 'Stimulus 로그 검증 / 디버깅 (최신 BLF/ASC)' 영역에 결과를 표시합니다.

3. 표시 항목
- 대상 Logical CAN / Message / Signal
- 로그의 대상 Message frame 수, Tx 수, Rx 수
- 후보 Signal의 Active/Original 값과 실제 sequence
- Active 값 로그 관측 YES/NO
- Active 이후 Original 원복 관측 YES/미확인
- CRC/Alive/Counter류 Signal의 실제 sequence 및 변화 여부
- 동일 Message 내 실제로 값이 바뀐 Signal 목록
- Active 값이 들어간 raw frame 일부

예시:
[LOG-VERIFY][MESSAGE] CAN1 PSS_DRV_FD_01_200ms: frames=4 (Tx=4, Rx=0)
[LOG-VERIFY][SEQUENCE] DPSS_StSldFwdMvBtn: ... 1 -> 2 -> 1
[LOG-VERIFY][RESULT] Active 값 로그 관측=YES / Active 이후 Original 원복 관측=YES
[LOG-VERIFY][CRC/ALIVE] PSS_DRV_FD_AlvCnt1Val: ...
[LOG-VERIFY][CRC/ALIVE] PSS_DRV_FD_Crc1Val: ...

4. 중요 해석
- Active 값 로그 관측 YES = 해당 Message/Signal 값이 실제 로그에 기록되었다는 뜻입니다.
- 이것만으로 CRC/Alive가 유효했다거나 ECU가 Frame을 수용했다거나 실제 시트가 움직였다는 뜻은 아닙니다.
- 따라서 다음 3가지를 분리해서 해석합니다.
  A) PassFail CAPL 호출 성공
  B) BLF/ASC에서 실제 Active 값 관측
  C) 실제 차량 기능 반응

5. 기존 단일/다중 판정 영향 없음
- 기존 단일/다중 로그 재검토는 기존처럼 Rx-only parser를 사용합니다.
- rev85의 Tx/Rx 양방향 parser는 차량 송수신 테스트의 Stimulus 디버깅에만 사용합니다.
- 로그 자동검증 실패/미관측이 기존 FinalCheckResult 또는 Stimulus ok/restore_ok를 바꾸지 않습니다.

6. 수동 재검증
- 자동 분석 시 로그가 아직 쓰기 중이거나 최신 로그 탐색이 실패했다면 Measurement Stop을 확인한 후
  [마지막 Stimulus 로그 다시 검증]을 누르면 현재 자동 로그 폴더의 최신 BLF/ASC를 다시 분석합니다.

7. 사전 조건
- 설정 탭의 '자동 로그 폴더'가 올바르게 지정되어 있어야 합니다.
- 해당 CAN의 DBC가 지정되어 있어야 합니다.
- CANoe Logging branch/filter가 확인하려는 Message, 특히 Stimulus Tx를 실제로 기록하도록 구성되어 있어야 합니다.
- BLF 분석에는 기존과 동일하게 python-can, DBC decode에는 cantools가 필요합니다.

8. 현장 확인 포인트
- PSS_DRV_FD_01_200ms / DPSS_StSldFwdMvBtn=2 시험 시
  1) Tx frame 수가 1개 이상인지
  2) DPSS_StSldFwdMvBtn sequence에 2가 존재하는지
  3) 원복 값이 Active 이후 다시 보이는지
  4) PSS_DRV_FD_AlvCnt1Val / PSS_DRV_FD_Crc1Val이 반복 frame마다 어떻게 변하는지
  를 우선 확인하세요.
