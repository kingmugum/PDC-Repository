PassFail rev85 - Seat Slide Hold / DBC / Baseline 진단 안내
============================================================

1. 좌석 Slide Hold 정책
- TX/RX Hold 기본값: 2.2 sec
- SldFwdMvBtn / SldBwdMvBtn 계열 버튼은 약 2초 long-press 요구를 반영합니다.
- 사용자가 0.5 sec 등 2.0 sec 미만을 입력해도 해당 좌석 Slide 버튼만 실제 profile에서 2.0 sec로 보정합니다.
- 다른 일반 Stimulus Signal은 전역 2 sec minimum을 강제하지 않습니다.

2. DBC가 필요한가?
- 현재 CAPL Frame backend에는 DBC가 필요합니다.
- DBC는 Message length, Signal bit 위치, scaling/encode-decode에 사용됩니다.
- 현재 로그에서 DPSS/CRC/Alive가 decode되고 있으므로 DBC 자체는 이미 사용되고 있습니다.
- 그러나 DBC가 있다고 해서 OEM CRC/Alive/E2E 계산 규칙까지 자동으로 제공되는 것은 아닙니다.

3. rev85 baseline 비교
- PassFail이 COM/DBC Signal 값으로 재구성한 baseline raw payload와 같은 Stimulus 시간창의 첫 실제 RX raw frame을 byte 단위로 비교합니다.
- 예시 현장 데이터:
  intended baseline = FF FF 00 00 54 ...
  observed RX       = D5 3D 13 5F 55 ...
  → B0, B1, B2, B3, B4가 서로 다름
- 이 경우 [AUTO-DIAG][7/BASELINE]에 '재구성 baseline이 실제 bus frame을 대표하지 않을 수 있음'이 표시됩니다.

4. 해석 주의
- baseline mismatch가 곧 DBC 오류라는 뜻은 아닙니다.
- 가능한 원인은 COM Signal 값 stale/default, Message의 동적 상태 Signal, CRC/Alive/E2E, 다른 신호의 현재값 미획득 등입니다.
- 실제 Tx를 확실히 확인한 뒤에도 baseline mismatch/E2E 문제가 남으면 다음 단계는 '실제 최신 RX raw frame을 baseline으로 캡처한 뒤 target Signal만 overlay'하는 방식입니다.
- 그 이후 CRC/Alive/E2E를 유효하게 갱신하려면 별도 알고리즘/사양이 필요할 수 있습니다.

5. 권장 다음 시험 순서
1) rev85 기본 Hold 2.2 sec 그대로 좌석 전진 후보 실행
2) AUTO-DIAG에서 ASC 전체 Tx 기록 여부 확인
3) Target Active=2 로그 관측 여부 확인
4) 동일 ID Rx 지속 여부 확인
5) [7/BASELINE] intended vs observed RX 차이 확인
6) Active Tx가 실제 확인되면 CRC/Alive/E2E와 TC output Expected를 확인

※ 로그 증거와 실제 차량 기능 PASS는 계속 별도입니다.
