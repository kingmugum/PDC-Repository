Signal Export V2 - 배포 패키지 명명 규칙

[공식 형식]
Signal_Export_V2_YYMMDD_N.zip

[규칙]
1. YYMMDD는 패키지를 실제로 생성한 날짜이다.
2. N은 같은 날짜에 생성된 Signal Export V2 ZIP 패키지의 순번이다.
3. 같은 날짜에는 _1, _2, _3 ... 순서로 1씩 증가한다.
4. 날짜가 바뀌면 순번은 다시 _1부터 시작한다.
5. ZIP 패키지의 날짜별 순번은 내부 Python 모듈의 GUI/Main/Step별 revision과 독립적으로 관리한다.
6. 새 패키지를 만들 때 이 규칙 파일, package_manifest.json, Excel의 09_배포패키지관리 시트를 함께 갱신한다.

[현재 패키지]
Signal_Export_V2_260827_1.zip
생성일: 2026-08-27
현재 순번: 1
같은 날짜의 다음 패키지: Signal_Export_V2_260827_2.zip

[새 대화에서 복구하는 방법]
- 과거 대화가 없어도 현재 ZIP을 업로드한다.
- ZIP 파일명에서 날짜와 순번을 읽는다.
- package_manifest.json 및 SignalAuto_Requirements_Management_rev57_V2.xlsx의 09_배포패키지관리 시트로 규칙을 재확인한다.
- 같은 날짜의 여러 ZIP이 함께 있으면 가장 큰 N에 1을 더한다.
- 날짜가 달라졌다면 해당 날짜의 첫 패키지는 _1이다.
- 사용자가 ZIP 이름을 임의로 변경한 경우 manifest의 package_name/sequence를 우선 확인한다.

이 규칙은 채팅 기억에 의존하지 않고 파일 자체에서 복구할 수 있도록 유지한다.
