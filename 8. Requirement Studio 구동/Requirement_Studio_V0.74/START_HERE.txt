Requirement Studio V0.74
========================

1. Requirement Studio.pyw 또는 main.py를 실행합니다.
2. 필요한 Source 문서는 `input` 폴더에 넣어 사용합니다.
3. 원하는 SWE.1 / SWE.6 산출물을 선택합니다.
4. 품질 평가 기본값 [3-AI 자동 평가 (추천)]을 사용하면 Review Package 생성 후 GPT/Gemini/Claude 평가가 이어집니다.

자동 평가 확인
--------------
- 시작 즉시 `review_exchange/<Run>/automatic_evaluation/00_EVALUATION_STATUS.txt`가 생성됩니다.
- 각 Reviewer 완료 즉시 해당 JSON/TXT가 저장됩니다.
- 최종 완료 시 `99_EVALUATION_COMPLETE.ok`가 생성됩니다.
- `final_result` 폴더에는 최대 110줄 단위 TXT가 생성됩니다.

평가 모드
---------
- 3-AI 자동 평가: Review Package + 실제 3-AI 호출
- 수동 평가 패키지만 생성: 로컬 Review Package만 생성, 외부 전송 없음
- 평가하지 않음: Review Exchange 자체를 만들지 않음

자동평가 진행률
----------------
- STEP 1~7 완료 후에도 `결과 품질 검토` 탭에서 자동평가 진행률을 계속 확인할 수 있습니다.
- GPT/Gemini/Claude 각각의 상태와 Consensus/Final Result/파일 검증 단계를 별도로 표시합니다.
- 100% 및 `완료` 표시는 결과 파일 재검증까지 끝난 상태입니다.

Gold Source
-----------
- V0.74는 프로그램 바깥에 `Requirement_Studio_Gold_Sources` 폴더를 생성하지 않습니다.
- 선택적 Gold 등록 데이터는 프로그램 내부 `review_exchange/gold_sources/user_registered`에 저장됩니다.
- 일반 사용은 기존처럼 `input` 폴더 중심으로 진행하면 됩니다.

중요
----
- API Key는 패키지에 저장하지 않습니다.
- Source/고객 문서의 외부 API 전송 가능 여부는 사내/고객 보안정책을 확인하십시오.
- 3-AI 일부만 완료된 결과는 PARTIAL이며 자동 Release PASS가 되지 않습니다.
- Requirements baseline은 rev58입니다. rev57 기존 승인 행은 수정/삭제하지 않고 V0.74 신규 요구사항만 append했습니다.

[V0.74 통합 평가]
- 결과 품질 검토 기본값은 `통합 End-to-End 평가 (SWE.1 + SWE.6)`입니다.
- 자동 평가에서는 Source/Canonical/SWE.1/Allocation/Child Intent/SWE.6/Actual Artifact를 한 Evidence Graph로 평가합니다.
- SWE.1/SWE.6 개별 모드는 디버깅용으로 유지됩니다.

[V0.74 FINAL_RESULT]
- FINAL_RESULT 파일 자체에 버전/Source/SHA/평가모드/Run ID가 들어갑니다. 별도 제목을 적지 않아도 됩니다.
- 분할 파일은 최대 110줄이며 각 Part에 식별 헤더가 반복됩니다.


[V0.74 Fact Fragment Ownership Precision]
- Exact ownership은 한 SRS에 연결된 모든 exact Source Fact Fragment의 합집합으로 판단합니다.
- critical signal/timing/enum/retry fact가 이미 매칭된 Source 범위 또는 Requirement가 명시적으로 인용한 동일 Source 위치의 누락 Fragment에 실제 존재할 때만 최소 Fragment를 보강 연결합니다.
- clear dominant parent가 있는 shared Fragment leakage는 weaker parent에서 제거하고, ambiguous sharing은 Review Needed로 남깁니다.
- Vision 분석이 없고 Requirement가 그림 의존성을 이미 명시한 경우 UNANALYZED_VISUAL_ASSET Gap/TBD를 생성합니다.
- `owned_fragment_fact_token_sources`로 token별 Fragment ID 근거를 남깁니다.
- Broad structured roll-up에만 있는 값은 exact Fragment ownership으로 인정하지 않습니다.
