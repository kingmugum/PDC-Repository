Requirement Studio V0.57 -> V0.58 변경 판단서
==============================================
기준일: 2026-09-30
대상 버전: Requirement Studio V0.58

1. 배경
------
V0.57은 no-ID 시스템사양서에서 Explicit-ID Coverage N/A 처리, Semantic Source Unit,
allocation/eligibility field, Gap dedupe, External Dependency 정규화, schema mismatch 제거를 달성했다.

실제 Cross-Document 재실행에서는 다음 잔여 문제가 확인되었다.
- high-confidence HW/Manufacturing/Electrical/Environmental item이 System pending으로 남음
- Review Needed item이 Main SWE.1 본문에 계속 포함됨
- Semantic Coverage는 비율만 있고 uncovered unit disposition audit가 없음
- dedupe 후 Gap enrichment에서 section gap이 다시 전체 SRS로 fan-out됨
- 일부 no-ID SRS의 Semantic provenance / Atomic Behavior가 비어 있음
- MAX/규제값을 <= 또는 equality requirement로 강화하는 semantic hallucination 위험

V0.58은 특정 MLM 문서 전용 보정이 아니라 위 failure pattern의 generic 원인을 수정한다.

2. 반영한 제안
--------------
[P0-1] High-confidence Not-SW Domain Assignment
- Connector/pin spacing -> Mechanical / Connector
- Soldering/coating process -> Manufacturing Process
- Current/rated voltage metric -> Electrical
- Operating/storage temperature/environmental qualification -> Environmental
- External reference-only fact -> External Standard Evidence Required
- 명사인 `제어기`, `동작 전압` 때문에 behavior 판정이 켜지는 false-positive를 제거한다.

[P0-2] Main SWE.1 / Allocation Annex Physical Separation
- Main SWE.1: swe1_eligibility=Eligible만 포함
- Review Needed: Allocation Review Annex
- Not Applicable: Cross-domain Allocation Annex
- Review Needed/Not-SW item은 삭제하지 않고 Canonical/Review Package/Annex에 유지한다.

[P0-3] Semantic Coverage Disposition Matrix
- semantic eligible unit 전체에 disposition_status / disposition_reason을 생성한다.
- COVERED_BY_CANONICAL
- NOT_SW_WITH_ALLOCATION_DECISION
- EXTERNAL_DEPENDENCY_ONLY
- REVIEW_NEEDED
- SEMANTIC_MISSING_POTENTIAL_EXTRACTION_LOSS
- coverage percent와 disposition coverage를 분리한다.

[P0-4] Gap Scope Link Filter
- dedupe 이전/이후의 link enrichment를 분리하고 최종 scope filter를 추가한다.
- document gap은 Requirement 직접 link를 제거한다.
- section gap은 location/token/external anchor가 있는 Requirement만 유지한다.
- broad section gap에서 deterministic anchor가 없으면 section_context_link로 남기고 전 SRS 연결을 금지한다.

[P0-5] Semantic Provenance Completeness Invariant
- no-ID SWE.1 Eligible: source_semantic_unit_ids + source_backed_atomic_behaviors 필요
- Pending System: Semantic provenance + behavior/fact review object 필요
- Not-SW: Semantic provenance + allocation + verification domain 필요
- Local QA는 Eligible invariant 위반을 error로 표시한다.

[P0-6] Comparator / Normative Strength Preservation
- Source literal `MAX`, label:value, 규제값/목표값을 자동으로 <=, =, >=로 확정하지 않는다.
- value_relation_status / normative_strength_status를 기록한다.
- 생성 문구가 Source보다 강해진 경우 Source literal 보존 문구 + clarification으로 되돌린다.

[P0-7] Semantic Unit Eligibility Classifier Refinement
- 목차, 문서 목적, 단순 규격/참조 목록은 denominator에서 제외한다.
- terse HW/Electrical/Environmental constraint는 behavior verb가 없어도 semantic review unit으로 보존한다.

[UX/QA] Local QA summary 명칭 정리
- 기존 explicit_count는 derivation_type=explicit Candidate 수이며 Explicit Source Requirement ID 수가 아니다.
- `explicit_statement_candidate_count` / `implicit_statement_candidate_count`로 명칭을 변경한다.

3. 그대로 반영하지 않은 제안 / 보수적으로 처리한 항목
------------------------------------------------------
[제외] Semantic classifier false-positive / false-negative 정확도 수치 자동 생성
- 사람 라벨 Gold Source Unit set이 없는 상태에서 precision/recall을 계산하면 허위 품질지표가 된다.
- V0.58은 eligible/review-context/unit-type count만 기록하고 ground_truth_precision_recall=null로 둔다.

[보류] 모든 uncovered semantic unit을 즉시 Missing Requirement로 확정
- no-ID mixed-domain 문서에서는 uncovered가 Not-SW, external reference, pending allocation일 수 있다.
- disposition별로 구분하고 실제 Source-backed SW behavior 미연결만 Potential Extraction Loss로 표시한다.

[보류] Timing/State/Variant intent별 TC를 숫자 맞추기 목적으로 자동 생성
- Source에 구체적 test value/transition evidence가 없으면 dedicated TC를 억지 생성하지 않는다.
- Required Intent와 Generated/Deferred reason의 분리는 유지한다.

[보호] Gold A Explicit-ID 동작
- 기존 occurrence/atomic behavior/regression single-truth 로직은 유지한다.
- no-ID semantic fallback이 explicit-ID evidence보다 우선하지 않는다.

4. Contract 변경
---------------

- Review Package Schema: 1.8 -> 1.9
- Protected Extraction Schema/Core는 변경 없음
