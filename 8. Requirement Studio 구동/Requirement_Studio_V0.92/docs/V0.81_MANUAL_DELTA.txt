Requirement Studio V0.81 Manual Delta
=====================================

1. 목적
-------
V0.81은 V0.80 Engineering E2E 구조를 유지하면서 실제 MLM/ESTRACK V0.80 Run에서 확인된 Generic Tool defect를 보정한다.
문서별 SRS/Signal/Paragraph를 하드코딩하지 않고 Source ownership, SWE.6 scope consistency, multi-model consensus 규칙을 일반화한다.

2. Shared Semantic Unit Ownership 강화
--------------------------------------
- 동일 Semantic Source Unit이 여러 Canonical SRS에 연결된 경우 material ownership을 비교한다.
- 한 Parent가 명확한 dominant owner이고 다른 Parent는 material/critical overlap이 없을 때에만 unrelated claim을 제거한다.
- 제거 시 Semantic Unit ID만 지우지 않고 파생 Source Fact Fragment, Atomic Behavior, Fact Allocation, Source-backed Fact, Table Fact Match 및 해당 Source evidence를 함께 정리한다.
- legitimate shared timing/signal/retry fact 또는 ownership이 모호한 경우 자동 삭제하지 않고 REVIEW_REQUIRED로 유지한다.
- ownership 정리 후 allocation/domain/SYS-SWE projection을 다시 계산하여 stale domain contamination을 방지한다.

3. SWE.6 Parent ↔ Fact Scope Consistency
----------------------------------------
- software-like Source action vocabulary에 `송출`을 추가한다.
- inferred controller SW candidate의 child fact가 literal executable action을 포함하면 fact-level inferred scope를 유지할 수 있다.
- fact-level allocation이 존재하는 Parent가 SWE.6 Eligible인 경우 Eligible fact가 최소 1개 존재해야 한다.
- Eligible fact가 0개이면 `Deferred - Fact Allocation Review`로 명시 전환하고 Human Decision/Release HOLD를 유지한다.
- Source에 없는 TC 값/환경/판정 기준은 생성하지 않는다.

4. Multi-model Finding Semantic Dedup
-------------------------------------
- GPT/Gemini/Claude가 동일 결함을 서로 다른 Category로 표현해도 concrete affected ID + specific failure concept가 일치하면 동일 Consensus Finding으로 묶는다.
- Eligible/zero-TC와 같이 세 Reviewer가 같은 invariant failure를 보고하면 STRONG_CONSENSUS로 집계한다.
- 같은 SRS를 언급해도 allocation approval, execution readiness 등 failure concept가 다르면 병합하지 않는다.

- V0.81 regression: RT-417~422 추가
- 전체 Python regression suite: 164/164 PASS
