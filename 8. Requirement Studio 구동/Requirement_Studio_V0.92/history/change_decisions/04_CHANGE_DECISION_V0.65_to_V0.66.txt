Requirement Studio V0.65 -> V0.66 Change Decision
=================================================

Decision
--------
V0.66 is a Hardening + Automated Evaluation build.
The extraction/canonical philosophy remains unchanged: preserve Source facts, do not invent missing facts,
and keep uncertain allocation/testability explicit.

Why V0.66
---------
The V0.65 SWE.6 Reference Run confirmed major V0.64 fixes, but exposed four remaining engineering risks:
1) Watchdog Child Intent retained the Semantic Unit but lost source_fact_fragment_id.
2) Composite Paragraph 82 no longer caused allocation conflict, but some SRS still over-owned weakly related fragments.
3) SRS_007 combined SWE.6-eligible SW recovery and SYS.5 state-equivalence facts in one generic TC scope.
4) Capture field existence was not explicitly proven by the actual-XLSX contract.

The user also requested removal of the manual H-Chat copy/paste evaluation loop. The program should be able to
send the exact same evaluation evidence independently to GPT, Gemini and Claude, persist structured results,
calculate consensus, and generate hand-off TXT files automatically.

V0.66 Changes
-------------

P0-1. Fragment -> Atomic -> Child Intent identity completion
- Existing atomic behavior text that materially matches an owned Source Fact Fragment now inherits the exact
  source_fact_fragment_id, chunk and location instead of merely suppressing duplicate backfill.
- Tool Quality audit emits CHILD_INTENT_SOURCE_FACT_FRAGMENT_LINK_MISSING when a Source-backed Child Intent has
  a Semantic Unit link but no fragment identity while the SRS owns Source Fact Fragments.
- Watchdog-style software structural constraints are explicitly covered by regression.

P0-2. Minimum material Source Fact ownership
- Fragment ownership is based on Canonical behavior fields, not re-use of the full Source Evidence paragraph.
- The ownership selector keeps the minimum materially related trigger/action/output fragments and excludes
  unrelated neighboring clauses.
- Complementary clauses such as receive + store or receive + control may both be owned when both materially
  contribute to the Canonical requirement.
- True ordered lists keep materially represented members; table/decimal preservation from V0.65 remains intact.

P0-3. Mixed-domain SWE.6 TC scope
- If a parent SRS contains both SWE.6-eligible and non-SWE.6 facts, the generated TC asserts only the
  SWE.6-eligible fact scope.
- SYS.5, external-dependency, and allocation-pending facts remain visible as excluded/deferred audit evidence.
- A parent SRS may remain one review bundle; V0.66 does not mechanically split SRS merely to improve metrics.

P0-4. Capture export contract
- SWE.6 column U 'Capture CANoe (Optional)' is an explicit workbook-schema field.
- User entry is optional, but the header must exist.
- Actual XLSX artifact verification checks R/S/T/U headers and verifies all four result fields are physically blank
  before execution.


P1-1. Raw literal / failure-handling fact precision
- Detached closing punctuation such as `...없다. )` is retained in source_excerpt_raw while display text may remain normalized.
- Conditional error/recovery statements are classified as FAILURE_HANDLING_REQUIREMENT rather than PROHIBITION unless an explicit negative normative relation exists.

P0-5. Independent 3-AI automated evaluation
- New core/evaluation_orchestrator.py.
- The same Evaluation Evidence Package is independently reviewed by GPT, Gemini and Claude.
- Reviewers do not see one another's results before consensus.
- Default transport is the existing H-Chat gateway. Optional direct_api transport is configurable.
- API keys are not stored in the package; direct API mode uses environment variables.
- Structured reviewer JSON is persisted first, then rendered to TXT.

Generated evaluation outputs
----------------------------
automatic_evaluation/
  01_GPT_EVALUATION.json + .txt
  02_GEMINI_EVALUATION.json + .txt
  03_CLAUDE_EVALUATION.json + .txt
  04_EVALUATION_CONSENSUS.json + .txt
  05_EVALUATION_RESULT.json
  AUTOMATIC_EVALUATION_MANIFEST.json
  final_result/
    FINAL_RESULT_001.txt
    FINAL_RESULT_002.txt ...
    manifest.json

Final-result split rule
-----------------------
- Consolidated human-readable result is split deterministically at 150 lines per TXT file.
- No finding content is intentionally dropped to satisfy the split.
- final_result/manifest.json records total lines, part count, per-file line count and SHA-256.

Consensus governance
--------------------
- 3/3 = STRONG_CONSENSUS
- 2/3 = CONSENSUS
- 1/3 = SINGLE_REVIEWER / human-review candidate
- A FAIL/HOLD is never hidden by majority voting.
- If fewer than all three reviewers complete, useful findings are retained but evaluation completeness is PARTIAL
  and the automated evaluator cannot independently declare Official Release PASS.

Evaluation transport
--------------------
Default: hchat
- Reuses the existing H-Chat GPT/Gemini/Claude adapters and H-Chat credentials.

Optional: direct_api
- OpenAI: Responses API + JSON Schema structured output
- Gemini: Interactions API + response_format JSON Schema
- Anthropic: Messages API + output_config.format JSON Schema
- Configure in config/evaluation_api_config.json and environment variables.

Security / data handling
------------------------
- Automatic evaluation is user-visible and can be switched OFF.
- When ON, the Evaluation Evidence Package is transmitted to the configured H-Chat/API reviewers.
- The package contains no API secret.
- Organization/customer policy must permit transmission of the selected Source/evidence to the configured service.

Contract versions
-----------------
- Canonical Schema: REQ-STUDIO-CANONICAL-REQ-2.0 (unchanged)
- Review Package Schema: 2.5
- SWE.1/SWE.6 Mapping: 2.2
- Protected Invariants: 1.6
- Automated Evaluation Schema: 1.0

Release posture
---------------
V0.66 remains a Hardening Build until actual Source E2E execution is reviewed.
Passing synthetic/unit regression does not substitute for an approved same-source Gold regression.
Correct Source insufficiency may still produce Artifact Readiness REVIEW_REQUIRED without Tool Quality failure.
