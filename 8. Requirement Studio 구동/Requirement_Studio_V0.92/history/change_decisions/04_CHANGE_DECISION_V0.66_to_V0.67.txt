Requirement Studio V0.66 -> V0.67 Change Decision
=================================================

Decision: ACCEPT AND CONSOLIDATE
Date: 2026-10-02
Build Type: Reviewer-path consolidation / requirements-baseline correction

Why V0.67
---------
V0.66 introduced a real post-Review-Exchange GPT/Gemini/Claude evaluation orchestrator.
However, the UI still retained the V0.45-era quality-review concept:
- standard review
- duplicate review
- precise review
- first/second/third reviewer selectors
- flagged/all scope selector
- per-criterion toggles

Code inspection confirmed that the legacy reviewer UI collected settings and wrote them to Review Package metadata/logs, but did not execute reviewer E2E calls. The new V0.66 orchestrator used its own provider/evaluation configuration, so the two paths could appear equivalent to the user while not sharing execution authority.

V0.67 Decision
--------------
1. Keep the V0.66 real 3-AI evaluation orchestrator.
2. Remove the dormant legacy standard/duplicate/precise reviewer-selection workflow.
3. Make evaluation mode explicit and singular:
   - AUTO: build Review Exchange, then independently call GPT/Gemini/Claude.
   - MANUAL: build local Review Exchange only; no external call.
   - NONE: do not build Review Exchange and do not call external reviewers.
4. Keep SWE.1/SWE.6 evaluation-artifact selection.
5. Keep six review axes as fixed evaluation contract rather than misleading optional toggles.
6. Reviewer model authority comes from the actual evaluation/provider configuration, not a disconnected GUI selector.
7. Reviewer findings remain review opinions and never become Source Evidence automatically.

Requirements Exception
----------------------
The user explicitly allowed Requirement Specification modification for this consolidation only.
Accordingly:
- Requirements baseline changes from rev54 to rev55.
- ALR-SC-086 is rewritten around actual independent 3-AI evaluation.
- FR-316 is replaced in place with UnifiedEvaluationUI.
- FR-362~FR-365 are added for IndependentTriad, ConsensusGate, FinalResultSplit, and TransmissionBoundary.
- Related acceptance criteria, failure scenarios, regression tests, code evidence, AI rules, and conflict-resolution records are updated.

Protected Invariant
-------------------
Protected Invariants 1.7 adds INV-029:
Legacy reviewer selectors must not coexist as an active reviewer contract with the GPT/Gemini/Claude orchestrator. Auto/manual/none transmission boundaries are explicit.

Release Intent
--------------
This change does not alter Canonical Requirement truth, SWE.1/SWE.6 allocation rules, Source Fact Fragment semantics, or the V0.66 evaluation schema/consensus content. It removes a misleading legacy control surface and aligns the UI/requirements with the code path that actually performs review.
