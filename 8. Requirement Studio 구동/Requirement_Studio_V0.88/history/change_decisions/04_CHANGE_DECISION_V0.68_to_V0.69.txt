Requirement Studio V0.68 -> V0.69 Change Decision
===================================================
Date: 2026-10-02

1. Change purpose
-----------------
V0.68 persisted automatic-evaluation status/results correctly, but the main pipeline progress ends at STEP 7. Users therefore had no GUI-native way to see whether GPT/Gemini/Claude review, Consensus, final_result generation, or output verification was still running.

V0.69 adds a dedicated progress monitor only inside the Result Quality Review tab. It does not add an eighth main pipeline step and does not change the locked requirements workbook.

2. Automatic-evaluation progress contract
-----------------------------------------
The GUI polls `automatic_evaluation/00_EVALUATION_STATUS.json` and displays stage-based progress:
- BUILD_EVIDENCE: 5%
- PROVIDER_REVIEW: 15% start, up to 75% as reviewers finish
- CONSENSUS: 82%
- FINAL_RESULT: 90%
- OUTPUT_VERIFY: 96%
- OUTPUT_VERIFIED: 100%

Provider states are displayed independently as WAITING/RUNNING/COMPLETED/FAILED/DISABLED. Exact token-level progress is not claimed because provider APIs do not expose a stable cross-provider token-progress contract.

3. V0.68 automated-evaluation findings addressed
-------------------------------------------------
- Korean/ASCII engineering literals such as `최초B+` are tokenized across script boundaries for semantic ownership matching without rewriting raw Source text. This prevents the fourth High Power Mode condition from being dropped solely because Source and Canonical spacing differ.
- When one parent SRS contains mixed SWE.6 and non-SWE.6 fact domains, parent-level expected-result prose is no longer echoed back into the SWE.6 TC description. Non-SWE.6 facts remain only in explicit excluded/deferred audit context.

4. final_result handoff
-----------------------
`FINAL_RESULT_###.txt` remains the normal human/ChatGPT handoff. One file is expected whenever the rendered final result is <=150 lines. Provider-specific 01/02/03 files are diagnostic supplements only when reviewer disagreement or a suspected false positive requires deeper inspection.

5. Requirements baseline
------------------------
`Requirement_Studio_Requirements_Management_rev55.xlsx` is unchanged byte-for-byte in V0.69. No requirement row or locked governance rule is edited.
