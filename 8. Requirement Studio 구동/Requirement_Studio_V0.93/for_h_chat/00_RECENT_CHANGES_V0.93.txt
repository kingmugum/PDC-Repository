Requirement Studio V0.93 Manual Delta
=====================================

1. Human-facing Review Reason
- E2E 평가 Main의 `검토 사유 / 필요 조치`는 가능한 범위에서 한글로 표시합니다.
- Raw enum/영문 required_resolution은 Trace/JSON에서 변경하지 않습니다.

2. Requirement Meaning-unit Numbering
- E2E 요구사항 `요구사항 내역`은 새로운 행/열/SRS를 만들지 않고 동일 셀에서 독립 의미 문장마다 ① ② ③ 번호를 부여합니다.
- Source/Canonical JSON은 변경하지 않는 Presentation-only 기능입니다.

3. TC Decomposition Refinement
- 명시적 Binary/Semantic Branch가 서로 다른 Engineering 의미를 만들고 독립 판정 가능하면 branch별 TC 분리를 우선할 수 있습니다.
- 서로 다른 Timing Checkpoint가 각기 다른 시작 조건/시간 한계/판정 조건을 가지면 checkpoint별 별도 TC로 분리합니다.
- 동일 Decision Function의 대규모 조합 표는 1 TC + N Vector 원칙을 계속 우선합니다.

4. Guideline Mining
- `policy/decision_example_registry.json`: 명시적인 사용자 판단 사례
- `core/guideline_mining.py`: Decision Factor 추출, Candidate Rule 생성, Counterexample 분석
- `policy/guideline_rule_registry.json`: 사용자 승인 Rule/Heuristic
- Candidate Rule은 자동 승격되지 않습니다. HUMAN_APPROVED Rule만 실제 생성 로직에 영향을 줍니다.

5. Exact Fact Trace Hardening
- Grouped Format/Resolution 같은 TC에서 한 Vector에 exact Fact Fragment가 없으면 case 전체 Exact Field Trace PASS를 허용하지 않습니다.
- 해당 항목은 REVIEW_REQUIRED로 전환합니다.

6. Package Hygiene
- API Key 폴더와 input 폴더의 깨진 README TXT는 배포하지 않습니다.
- 두 폴더는 `.gitkeep`을 유지합니다.

7. Scope Boundary
- EP/BVA/Fault Injection 자동 확장 없음
- 자동 Rule promotion 없음
- 기존 Source Fidelity / Review/Hold / Single Truth / LOCK-008 원칙 유지
